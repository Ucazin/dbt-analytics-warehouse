What it signals

dbt is the de-facto transformation layer for analytics in 2026. It appears in nearly every US/CA data-team job posting and in zero of the comparable junior portfolios I surveyed. This repo is the artifact that says this person can ship into our stack on day one.

What's modeled

  • 5,000 customers in an 8-country split, with subscriptions, orders, and a 200-SKU product catalog.
  • 24 months of MRR snapshots across Starter / Growth / Pro tiers — ending at $1.3M.
  • Six marts: dim_customer, dim_product, dim_date, fct_orders, fct_mrr_movement, fct_subscription_snapshot.
  • One snapshot — SCD-2 history on the customer dimension. The pattern production teams use to audit changes after the fact.
  • Two exposures — the Power BI dashboard and the Streamlit funnel app downstream. dbt run --select +executive_dashboard resolves the full upstream chain.
The discipline that matters. Every column has a description. Every model has a purpose statement. Every key has a uniqueness test. A reusable macro converts cents to dollars in four different models — DRY SQL, not copy-paste. This is what production-grade looks like.

The lineage graph

Auto-generated from target/manifest.json by a small Python script in scripts/render_dag.py. The repo commits the rendered PNG so a reviewer doesn't need to install dbt to see the shape of the project.

Portability

  • DuckDB locally — zero credentials, zero setup, runs in seconds.
  • Snowflake / BigQuery / Redshift — change one profile, the SQL is portable.
  • CI-ready — Makefile + idempotent scripts → drops cleanly into GitHub Actions.
